# V0.4 Architecture

Council of Translation separates its FastMCP boundary from a testable Council Core. FastMCP adapters implement model sampling and user elicitation; scripted adapters exercise the same orchestration without Goose or live models.

## Pipeline

1. Deterministic preflight extracts named/braced/printf placeholders, variables, commands, tags, URLs, explicit do-not-translate literals, and machine-readable caller hard constraints. Placeholder, required token, markup, URL, and explicit literal loss can block. Numeric and Markdown differences are warnings unless promoted by `numeric_parity` or `markdown_parity`; `required_literal:<text>` and `forbidden_literal:<text>` enforce exact caller requirements. Other free-form TB/SG/project/technical packets guide reviewers but cannot become deterministic blockers by model assertion alone.
2. `CouncilPlan` selects executable reviewer roles by mode and content type. The chief editor is an adjudicator, not an independent reviewer.
3. Independent role calls return bounded natural `role_feedback` plus conservative `FindingV2` evidence. Model output cannot create hard constraints or blockers.
4. Findings are clustered by normalized issue family and text anchors. Production logic contains no named-example conflict shortcuts.
5. Standard and strict modes may run one discussion round: standard considers at most one issue/three roles; strict at most two issues/four roles. Lightweight skips discussion.
6. Up to three meaningful DecisionPoints are collected in one elicitation form. Only non-material language-choice issues are eligible; correctness, risk, integrity, critical, and major issues cannot be turned into preference questions. Invalid options are removed before interaction.
7. Accepted decisions trigger one batched reconsideration call per affected role. `continue_review` deep-copies the prior record, links `parent_review_id`, and does not rerun independent reviews.
8. The Policy Gate protects immutable constraints. The chief editor uses evidence provenance, constraint tier, relevance, blocking state, and confidence; role counts are not a decision rule.

## Safety and budgets

All MCP payloads and model outputs are untrusted. Prompts delimit data, request structured claims/evidence instead of hidden reasoning, and constrain output sizes. Malformed samples degrade to non-blocking missing evidence.

Call budgets are enforced at 6/10/14 for lightweight/standard/strict. There is at most one discussion round, one elicitation form, three DecisionPoints, and one reconsideration call per affected role.

## Storage

`ReviewStore` uses atomic replacement and validates record IDs before access. `full`, `metadata`, and `off` privacy modes are explicit. Metadata persistence is allowlist-based. V2 storage is searched before the optional legacy working-directory reader; legacy records without `schema_version` parse as V1.
