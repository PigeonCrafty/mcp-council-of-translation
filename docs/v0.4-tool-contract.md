# V0.13.1 Tool and Data Contract

## Defaults and surface

Exactly five normal tools are registered: `review_translation`, `continue_review`, `view_review_record`, `list_review_records`, and `get_server_info`. Diagnostic build is `truthful-boundaries-council-v11.1`; package and module version are `0.13.1`; the write schema is `2.6`, the derived verification receipt schema is `1.1`, and the offline evaluator schema is `2.1`.

`review_translation` requires source text and candidate translation. `briefing_mode` accepts `auto` (default), `always`, or `off`. `mode` accepts `lightweight`, `standard` (default), or `strict`. `output_mode` accepts `review_only` (default), `with_snippets`, or `full_rewrite`; `interactive_mode` accepts `auto` (default), `off`, or `required`; `decision_fallback` accepts `council_adjudication` (default) or `return_pending`; `trace_level` accepts `summary` (default) or `full`; and `history_mode` accepts `full` (default), `metadata`, or `off`. Invalid enum-like option strings normalize to conservative documented defaults.

Context fields include languages, content type, audience, TB/SG/project/brand/technical rules, do-not-translate literals, references, exceptions, and notes. Machine-enforced `hard_constraints` are `numeric_parity`, `markdown_parity`, `required_literal:<text>`, and `forbidden_literal:<text>`. Other free-form rule text remains reviewer context and cannot be promoted to a deterministic blocker by model output alone.

Routing is deterministic and sampling-free. Normalized `content_type` and `mode` select one of 15 fixed profiles; no free-text field is inspected. Non-legal portfolios remain frozen. `legal_risk` uses fidelity, terminology, risk/ambiguity and fluency in lightweight; adds product-context and UX-copy in standard; and adds technical safety in strict. Compact, full and metadata records expose only bounded routing profile/reason provenance. Historical V2.0-V2.4 records without these fields remain readable with conservative unrecorded-routing defaults.

Only independent reviewer sampling is concurrent. `COUNCIL_REVIEW_CONCURRENCY`
accepts the exact values `1`, `2`, and `3`; missing configuration defaults to `3`, and
empty, non-numeric, or out-of-range values use `1` with `invalid_fallback`. The server
reserves all independent calls before launch, attempts each role once without replay,
and restores Council-plan order after the complete batch settles. `get_server_info()`
reports the normalized effective limit, maximum supported value `3`, and disposition;
it never exposes the raw environment value.

## Output and interaction

The three human-facing tools—`review_translation`, `continue_review`, and `view_review_record`—return a dual-channel MCP result. Its first text block is the bounded user-facing Council report; its structured content is the complete existing compact or full dictionary. The primary report uses exactly the five sections `审校背景`, `Council 新增视角`, `角色覆盖与分工`, `共识、分歧与盲区`, and `主编结论`, targets <=1,200 Unicode code points for the clean reference case, and is always <=3,200. Confirmation-only roles share one coverage line. Primary human work items use deterministic check provenance and bounded protected anchors to join repeated checks with matching reviewer corroboration; model-only cross-category findings join only when exact source/candidate anchors and a non-empty replacement agree. Known deterministic failures render as natural Chinese, while different literals, repair families and replacement actions remain distinct and material consequences remain visible. This is a display projection only: full chief rationale, checklist, raw clusters, RoleLens evidence and value metrics remain unchanged in structured content. It suppresses canonical adjudication counters and redundant evidence for clean roles only; blockers, whole material evidence, minority conditions, context and coverage gaps, degradation and warnings remain, and the final editor disposition is last. `trace_level="full"` returns the complete V2.5 record in structured content; otherwise `view_review_record` retrieves it only when `history_mode="full"`. Metadata history deliberately cannot reconstruct a full trace. `list_review_records` and `get_server_info` remain structured-only tools.

In `briefing_mode=auto`, insufficient source/candidate-only context requests at most six flat fields before any model sample. Rich context skips; `always` requests and returns sampling-free pending on non-accept; `off` proceeds with explicit assumptions. Categorical fields include `不确定，由 Council 推断`, and accepted answers preserve field provenance. Reviewers may return optional material `context_gaps`. Invalid gap entries do not invalidate findings; Core selects at most two unanswered nonduplicate questions using bounded impact grammar, including brand-versus-functional use and binding glossary/reference applicability. Accepted actual answers update the brief and reconsider only affected active roles. Assumption, decline, cancel, unsupported, malformed or error leaves selected material context unresolved, prevents outcome elicitation and returns human-review status with bounded warning/fallback provenance. Context and outcome reconsideration records remain separate.

`interactive_mode="auto"` elicits only for a meaningful non-material language choice with at least two valid, distinct local outcomes. Only a validated `choice` finding with a non-empty bounded `proposed_value` contributes a proposed outcome; `action` stays non-selectable advice for issue, affirmation, legacy, invalid, and incomplete classifications. A consistent bounded `candidate_span` supplies the current outcome; when known it is first, alternatives follow, and explicit `暂不决定，由 Council 裁决` is last. Proposed replacements must have one provable anchor in the complete candidate. The server reconstructs that complete candidate before deterministic checks, so unrelated protected material remains in scope. Missing/repeated anchors create bounded content-free Policy Gate suppression records, `decision_suppressed:<reason>` compact warnings, `degraded=true`, and `decision_validation_degraded` fallback provenance. Actual protected-token loss is an ordinary Policy Gate rejection, not anchor degradation. Each field exposes no more than four choices, with labels limited to 48 Unicode code points and descriptions to 160. The actual enum literals are concise readable values such as `保留：继续` and `改为：下一步`; a per-field mapping round-trips them to exact internal options, and readable suffixes resolve display collisions. Internal IDs, hash surrogates, and full reviewer prose are not shown. One submit button for the batched form is normal. Explicit delegation invokes Council adjudication and is distinct from unsupported, declined, cancelled, malformed, stale, or runtime-error interaction. `decision_fallback="return_pending"` requires `history_mode="full"`, produces `RETURNED_PENDING`, and includes bounded DecisionPoints in the compact response.

`continue_review` accepts a list of objects containing required `decision_id` and `selected_option_id` keys. Optional fields are `classification`, `context`, and `authority_mode`. Unknown decisions and invalid options are rejected. A successful continuation creates a new review ID with the original as `parent_review_id`.

## Structured trace

`process_digest` retains this fixed field order: case brief;
assumptions/context confidence; blind spots; role lenses; consensus; minority report
with a decisive counterfactual; material disagreements; context gaps/answers; user
decisions; reconsideration changes; editor synthesis; execution checklist/final
disposition. Every active reviewer retains a bounded role lens. `display_report`
compresses that material into the adaptive section order documented above and remains
review-only. Internal role/decision/option IDs are not shown in primary text.

`ReviewRecordV2` schema 2.6 retains guided briefing, context gaps/answers, separate context/outcome reconsideration provenance, phase trace, process digest, display report, routing, content-free runtime telemetry and `council_value_metrics`. It adds one bounded `decision_support` object targeting the chief disposition. Its level is `well_supported`, `supported_with_limits`, or `insufficient`; codes are canonical structured facts, not numeric confidence, model self-confidence, voting or a quality probability. Context confidence describes the brief, coverage describes valid planned-role envelopes, decision support describes the disposition's evidence basis, and publishability remains the chief outcome. Only insufficient support can tighten a permissive outcome to human review. V1/V2.0-V2.5 expose this object as historically `not_recorded`.

Each reviewer has at most one fixed total Position Matrix influence per issue. Identical same-role/action findings retain their individual finding records but collapse to one matrix row; distinct actions from that role share the fixed influence deterministically. Runtime metadata reports structured reviewer successes, unavailable reviewers, and `full`/`partial`/`none` coverage. JSON decoding alone is insufficient: a successful envelope contains string `role_feedback`, list `findings`, and only safely validated object entries. Zero findings require non-blank feedback. The chosen conservative policy discards all findings if any entry is invalid and marks the sample unavailable. Partial or zero coverage sets an explicit coverage fallback and requires human review; malformed, reasoning-only, empty, transport-error, invalid-JSON, or semantically invalid output is never interpreted as a clean review. This adds no retries and does not claim live Goose/provider verification.

The chief checklist uses semantically deduplicated `must_fix`, `should_fix`, `optional_improvements`, `terminology_decisions`, `conflict_resolutions`, and `execution_order`. Affirmations are not improvements. Selected internal IDs are resolved to readable outcomes in this compact checklist. Review-only output never claims to edit files and does not include a full recommended translation. Only explicit `full_rewrite` may include one.

Metadata history uses an explicit allowlist for IDs/timestamps, task and plan modes, safe context confidence/content type, input diagnostics, phase interaction/reconsideration counts, runtime/version metadata, `status`, `degraded`, `publishability`, and `review_needed`; it redacts source/candidate text, rule packets, briefing free text, context questions/answers, display Markdown, compact derived prose, model/user/chief prose, and secrets. Persistence write/replace failures return a normalized error without raw host paths.

## Compatibility

`view_review_record` and `list_review_records` support V2.6, V2.5, V2.4, V2.3, V2.2, V2.1, V2.0, and V1 JSON. A record with no `schema_version` is V1. V2.0 findings migrate conservatively and do not gain hard/blocking authority. V1 summary retrieval exposes only schema, ID, mode, status and chief disposition; V1 full and verification retain their existing contracts. The public V0.3 response shape and obsolete debate/voting tools are not preserved when they conflict with current correctness.

`view_review_record` accepts `detail_level="full"`, `"summary"`, or `"verification"`. The opt-in verification view performs exactly one record load and returns only `review_id`, a bounded five-section technical Markdown report, and a canonical privacy-safe receipt. The receipt remains unchanged in structured content and the exact same in-memory object is compactly serialized as UTF-8-safe JSON after the Markdown/footer in the first text block for clients that ignore MCP structured content. It never saves, samples, elicits, orchestrates, or mutates the record. The receipt contains bounded codes and counts rather than source/candidate text, reviewer prose, evidence, actions, user answers, warnings, suggested translation text, internal issue IDs, paths, environment values, or secrets. Missing historical or metadata-only facts are `null` and enumerated; compatibility defaults are not recorded truth. This technical view supplements rather than replaces the normal process-first Council report, and existing full/summary projections are unchanged.

For normal-user Goose validation, install a reviewed commit with `uvx --refresh --from git+https://github.com/PigeonCrafty/mcp-council-of-translation@<reviewed-commit> mcp_council_of_translation`. Provide only source and candidate, manually answer the briefing when it appears, and ask for the Council review. The first final answer itself must show the five-section value-first process, account for every active role, preserve truthful consensus or uncertainty, and place the verdict last; it must not require a diagnostic checklist or a second history prompt. One submit button is expected for the batched standard form. `view_review_record(review_id, detail_level="full")` remains available when the user actually wants full structured evidence.
