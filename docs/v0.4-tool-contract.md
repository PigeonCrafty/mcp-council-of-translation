# V0.5 Tool and Data Contract

## Defaults and surface

Exactly five normal tools are registered: `review_translation`, `continue_review`, `view_review_record`, `list_review_records`, and `get_server_info`. Diagnostic build is `outcome-first-decision-v3`; package and module version are `0.5.0`; the write schema is `2.1`.

`review_translation` requires source text and candidate translation. `mode` accepts `lightweight`, `standard` (default), or `strict`. `output_mode` accepts `review_only` (default), `with_snippets`, or `full_rewrite`; `interactive_mode` accepts `auto` (default), `off`, or `required`; `decision_fallback` accepts `council_adjudication` (default) or `return_pending`; `trace_level` accepts `summary` (default) or `full`; and `history_mode` accepts `full` (default), `metadata`, or `off`. Invalid enum-like option strings normalize to conservative documented defaults.

Context fields include languages, content type, audience, TB/SG/project/brand/technical rules, do-not-translate literals, references, exceptions, and notes. Machine-enforced `hard_constraints` are `numeric_parity`, `markdown_parity`, `required_literal:<text>`, and `forbidden_literal:<text>`. Other free-form rule text remains reviewer context and cannot be promoted to a deterministic blocker by model output alone.

## Output and interaction

The default response is compact: record IDs/status, chief-editor checklist, `effective_task`, a bounded `deliberation_summary`, user decision/delegation, reconsidered roles, `degraded`, warnings, runtime counts, and a full-trace retrieval hint. `trace_level="full"` returns the complete V2.1 record inline; otherwise `view_review_record` retrieves it only when `history_mode="full"`. Metadata history deliberately cannot reconstruct a full trace.

`interactive_mode="auto"` elicits only for a meaningful non-material language choice with at least two valid, distinct local outcomes. A consistent bounded `candidate_span` supplies the current outcome; when known it is first, alternatives follow, and explicit `暂不决定，由 Council 裁决` is last. Proposed replacements must have one provable anchor in the complete candidate. The server reconstructs that complete candidate before deterministic checks, so unrelated protected material remains in scope while missing/repeated anchors and affected protected-token loss are rejected conservatively. Each field exposes no more than four choices, with labels limited to 48 Unicode code points and descriptions to 160. The actual enum literals are concise readable values such as `保留：继续` and `改为：下一步`; a per-field mapping round-trips them to exact internal options, and readable suffixes resolve display collisions. Internal IDs, hash surrogates, and full reviewer prose are not shown. One submit button for the batched form is normal. Explicit delegation invokes Council adjudication and is distinct from unsupported, declined, cancelled, malformed, stale, or runtime-error interaction. `decision_fallback="return_pending"` requires `history_mode="full"`, produces `RETURNED_PENDING`, and includes bounded DecisionPoints in the compact response.

`continue_review` accepts a list of objects containing required `decision_id` and `selected_option_id` keys. Optional fields are `classification`, `context`, and `authority_mode`. Unknown decisions and invalid options are rejected. A successful continuation creates a new review ID with the original as `parent_review_id`.

## Structured trace

`ReviewRecordV2` schema 2.1 adds finding classification/proposed outcomes, option outcome/provenance fields, explicit selection/delegation, reconsideration provenance, effective task, deliberation summary, degradation, and warnings. Position and DecisionPoint IDs share one deterministic issue/outcome identity. Safe discussion changes update the affected matrix row before adjudication. DecisionTrace distinguishes valid user choice, Council fallback, and human review and stores structured bases—not chain-of-thought.

Each reviewer has at most one fixed total Position Matrix influence per issue. Identical same-role/action findings retain their individual finding records but collapse to one matrix row; distinct actions from that role share the fixed influence deterministically. Runtime metadata reports structured reviewer successes, unavailable reviewers, and `full`/`partial`/`none` coverage. JSON decoding alone is insufficient: a successful envelope contains string `role_feedback`, list `findings`, and only safely validated object entries. Zero findings require non-blank feedback. The chosen conservative policy discards all findings if any entry is invalid and marks the sample unavailable. Partial or zero coverage sets an explicit coverage fallback and requires human review; malformed, reasoning-only, empty, transport-error, invalid-JSON, or semantically invalid output is never interpreted as a clean review. This adds no retries and does not claim live Goose/provider verification.

The chief checklist uses semantically deduplicated `must_fix`, `should_fix`, `optional_improvements`, `terminology_decisions`, `conflict_resolutions`, and `execution_order`. Affirmations are not improvements. Selected internal IDs are resolved to readable outcomes in this compact checklist. Review-only output never claims to edit files and does not include a full recommended translation. Only explicit `full_rewrite` may include one.

Metadata history uses an explicit allowlist for IDs/timestamps, task and plan modes, input diagnostics, runtime/version metadata, `status`, `degraded`, reconsideration counters, `publishability`, and `review_needed`; it redacts source/candidate text, rule packets, compact derived prose, model/user/chief prose, and secrets. Persistence write/replace failures return a normalized error without raw host paths.

## Compatibility

`view_review_record` and `list_review_records` support V2.1, V2.0, and V1 JSON. A record with no `schema_version` is V1. V2.0 findings migrate conservatively and do not gain hard/blocking authority. The public V0.3 response shape and obsolete debate/voting tools are not preserved when they conflict with current correctness.

For Goose validation, install a reviewed commit with `uvx --refresh --from git+https://github.com/PigeonCrafty/mcp-council-of-translation@<reviewed-commit> mcp_council_of_translation`, then call `get_server_info()` before the review. One submit button is expected for the batched standard form. Use `view_review_record(review_id, detail_level="full")` to inspect full evidence after the call.
