# V0.4 Tool and Data Contract

## Defaults and surface

Exactly five normal tools are registered: `review_translation`, `continue_review`, `view_review_record`, `list_review_records`, and `get_server_info`. Diagnostic build is `structured-deliberation-v2`; package and module version are `0.4.0`.

`review_translation` requires source text and candidate translation. `mode` accepts `lightweight`, `standard` (default), or `strict`. `output_mode` accepts `review_only` (default), `with_snippets`, or `full_rewrite`; `interactive_mode` accepts `auto` (default), `off`, or `required`; `decision_fallback` accepts `council_adjudication` (default) or `return_pending`; `trace_level` accepts `summary` (default) or `full`; and `history_mode` accepts `full` (default), `metadata`, or `off`. Invalid enum-like option strings normalize to conservative documented defaults.

Context fields include languages, content type, audience, TB/SG/project/brand/technical rules, do-not-translate literals, references, exceptions, and notes. Machine-enforced `hard_constraints` are `numeric_parity`, `markdown_parity`, `required_literal:<text>`, and `forbidden_literal:<text>`. Other free-form rule text remains reviewer context and cannot be promoted to a deterministic blocker by model output alone.

## Output and interaction

The default response is compact: record IDs/status, chief-editor checklist, blind spots, consensus/material disagreement summaries, user decisions, fallback reason, and runtime counts. `trace_level="full"` returns the complete V2 record inline; otherwise `view_review_record` retrieves it only when `history_mode="full"`. Metadata history deliberately cannot reconstruct a full trace.

`interactive_mode="auto"` elicits only for a meaningful non-material language choice among valid alternatives. Each field is a valid-option enum with a readable question/options description; the one batched message maps internal IDs to action labels and descriptions. Correctness, risk, integrity, critical, and major issues are never preference DecisionPoints. `off` uses fallback. `required` still terminates safely when elicitation is unsupported. Unsupported, declined, cancelled, or off interaction selects a valid non-tied option through the Position Matrix and records `council_fallback`; a real tie or insufficient evidence requests human review. `decision_fallback="return_pending"` requires `history_mode="full"`, produces `RETURNED_PENDING`, and includes bounded DecisionPoints in the compact response.

`continue_review` accepts a list of objects containing required `decision_id` and `selected_option_id` keys. Optional fields are `classification`, `context`, and `authority_mode`. Unknown decisions and invalid options are rejected. A successful continuation creates a new review ID with the original as `parent_review_id`.

## Structured trace

`ReviewRecordV2` contains normalized task/input diagnostics, runtime metadata, CouncilPlan, preflight, independent reviews, IssueClusters and RolePositions, bounded DiscussionTurns, DecisionPoints, UserDecisions, Reconsiderations, Policy Gate result, chief-editor decision, and DecisionTrace. Position and DecisionPoint IDs share one deterministic issue/action identity. Safe discussion changes update the affected matrix row before adjudication. DecisionTrace distinguishes valid user choice, Council fallback, and human review and stores structured bases—not chain-of-thought.

Each reviewer has at most one fixed total Position Matrix influence per issue. Identical same-role/action findings retain their individual finding records but collapse to one matrix row; distinct actions from that role share the fixed influence deterministically. Runtime metadata reports structured reviewer successes, unavailable reviewers, and `full`/`partial`/`none` coverage. A parsed JSON response with zero findings is successful coverage. Partial or zero coverage sets an explicit coverage fallback and requires human review; malformed, reasoning-only, empty, transport-error, and invalid-JSON output is never interpreted as a clean review. This adds no retries and does not claim live Goose/provider verification.

The chief checklist uses `must_fix`, `should_fix`, `optional_improvements`, `terminology_decisions`, `conflict_resolutions`, and `execution_order`. Selected internal IDs are resolved to readable actions in this compact checklist. Review-only output never claims to edit files and does not include a full recommended translation. Only explicit `full_rewrite` may include one.

Metadata history uses an explicit allowlist for IDs/timestamps, task and plan modes, input diagnostics, runtime/version metadata, `status`, `publishability`, and `review_needed`; it redacts source/candidate text, rule packets, model/user/chief prose, and secrets. Persistence write/replace failures return a normalized error without raw host paths.

## Compatibility

`view_review_record` and `list_review_records` support V2 plus V1 JSON. A record with no `schema_version` is V1. The public V0.3 response shape and obsolete debate/voting tools are not preserved when they conflict with V2 correctness.
